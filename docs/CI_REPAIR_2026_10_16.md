## Maintained lint-tooling decision (16 October follow-up)

Rechecked npm's current maintained releases after the feature work began:

- `@next/eslint-plugin-next@16.4.2` still declares `fast-glob: 3.3.1`.
- Latest `fast-glob@3.3.3` declares `micromatch: ^4.0.8`.
- Latest `micromatch@4.0.8` declares `braces: ^3.0.3`.
- Latest `braces` is still `3.0.3`, within the reported vulnerable range.

Therefore neither a supported Next ESLint upgrade nor a transitive override to those latest releases removes this chain. The installed Next config supplies framework rules, React Hooks/compiler checks, accessibility rules, import checks and TypeScript linting. Replacing it wholesale with a formatter or generic linter would lose coverage. A private fork, vendored glob replacement, or locally patched package would require security review and ongoing maintenance; it is not a maintained upstream fix.

Decision: retain the lint config and the failing high-severity audit gate, with no advisory suppression or threshold change. Preferred recovery is a maintained patched braces/micromatch/Next plugin release, then update the minimal chain and rerun audit, lint, units and build. An alternative is a separately reviewed migration to independently maintained plugins with a recorded rule-by-rule parity comparison and regression fixtures; that is broader than this CI repair and must not be presented as a quick dependency fix. No remote push is eligible while the current gate fails.
